# Проверки Devflow Diff Explain

Цель проверок — сохранить путь «описание и архитектура → блоки → файлы и полный дифф → важные строки → вопрос в чате». Целевой интерфейс — браузер на компьютере; отдельной приёмки для телефона нет.

## Обязательные команды

Перед коммитом:

```sh
pnpm -r typecheck
pnpm -r lint
pnpm -r test
```

`pnpm test:all` запускает тот же полный набор. После изменений серверных или UI-потоков дополнительно:

```sh
pnpm test:e2e
```

E2E собирают UI и CLI, запускают временные серверы и управляют Chromium через Playwright. Браузер устанавливается командой `pnpm --filter @sherpa/e2e exec playwright install chromium`; готовый бинарник можно передать через `SHERPA_E2E_EXECUTABLE_PATH`. E2E и другие команды сборки не следует запускать одновременно: они пишут одни и те же артефакты.

## Что проверяем

Новый контракт v5 проверяется на порядке «описание → схема → небольшие части файлов», точном составе назначений, сохранении прогресса после рестарта и знаменателя при локальном повторе. Desktop E2E проходит источники-ссылки, полный дифф, повтор схемы, восстановление файла/места/черновика после reload и явный переход к новому разбору. Сохранённые v2/v3/v4 проверяются отдельно как совместимость чтения.

| Слой | Основные инварианты |
|---|---|
| Протокол | Схемы, лимиты, совместимость версий и формы ответов |
| Сервер объяснения | Единственный сценарий генерации, постепенная готовность, отмена, повтор, рестарт, отказ невалидного результата |
| Сохранённый код | Полный патч, закреплённая итерация, сторона и непрерывный диапазон строк; отказ от подмены живым checkout |
| Схема потока данных | Независимая задача, ограниченные запросы контекста, подтверждённые и неизвестные связи, отказ/повтор |
| Чат | Явные вопросы, сохранённый контекст, приоритет над фоновыми задачами, retry и восстановление после сбоя записи |
| Хранилище и очередь | Транзакции, миграции без потери данных, аренды, идемпотентность, вытеснение воркера |
| UI | Порядок блоков и файлов, полный дифф, пояснения строк, сохранение места, защита от запоздавших ответов |
| Сборка и скилл | Standalone-бандлы, инструкция и маркеры рабочей петли, установка копированием |

`story.test.ts`, `readable-story.test.ts`, `guided-story.test.ts`, `explanation-runtime.test.ts` и тесты жизненного цикла проверяют текущий сервер. `explanation-compat.test.ts` и миграции отдельно проверяют чтение прежних данных. Тесты удалённых сервисов ревью удаляются вместе с этими сервисами, а общие инварианты остаются в тестах объяснения, очереди, чата и итераций.

Адаптеры источников тестируются на фикстурах и подменённых транспортах. Общий контракт адаптеров ещё включает унаследованные методы ревью; их наличие в контрактных тестах не означает, что рабочий сервер объяснения регистрирует эти возможности. Unit/integration-набор не должен зависеть от живого Arcanum или GitHub.

## Качество объяснения

Автоматические проверки подтверждают структуру, адресацию кода и поведение интерфейса. Они не доказывают, что рассказ понятно и верно объясняет архитектуру.

Для проверки на реальном PR последовательно прочитай описание, схему окружения, каждый смысловой блок и его файлы. Проверь, что понятны проблема, изменение поведения, роль файлов и причины важных строк; что мелкие детали не дублируют весь код; что пример не теряет условий; что переходы сохраняют место и вопрос получает показанную версию.

Рабочие находки, воспроизводимые данные и скриншоты сохраняются локально в игнорируемом каталоге `qa/`; он не переносится с Git-клоном. Если находка меняет требование или выявляет существенное ограничение, соответствующее действующее описание обновляется в `spec.md` или техническом справочнике. Публиковать комментарии в PR для проверки не требуется.

## Границы подтверждённого качества

Для приложения 0.17.0 с контрактом v5 и протоколом 0.18.0 проверены типы, линтер, полный unit/integration-набор и 13 desktop E2E. Они подтверждают механику обзора, частей файлов, прогресса, повтора, сохранения места и переключения результатов. Содержательная приёмка новой генерации на реальном PR не выполнена; успешные фикстуры её не заменяют.

В проверке чтения без агента есть известная нестабильность браузерного перехвата: переход на `about:blank` перед подменой живого SSE иногда зависает. Сбой продукта не подтверждён. При повторении нужно отделить проверку отключённого агента от навигации с открытым перехватываемым потоком; успешный повтор не устанавливает причину.
