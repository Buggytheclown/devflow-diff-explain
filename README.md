# Devflow Diff Explain

Личный инструмент, который проводит по PR от общей архитектуры к отдельным строкам кода: краткое описание проблемы и решения, схема потока данных с окружением изменения, смысловые блоки и упорядоченные файлы с полным диффом. Пояснения внутри файла выделяют важные места; детали можно спросить в чате с привязкой к строкам.

Целевой интерфейс — браузер на компьютере. Сервер хранит импортированные снимки и предоставляет чтение, объяснение и чат; не публикует комментарии и вердикты, не ведёт ревью-отметки и не запускает исправления кода. Сохранённые разборы доступны для чтения без подключённого агента.

## Установка и обновление

Нужны Node ≥ 22.13 и pnpm версии из `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm install:local
```

Установщик собирает приложение и копирует шесть проверенных файлов, включая метаданные вызова и отдельную команду Arc-экспорта, в `~/.agents/skills/devflow-diff-explain`. Симлинки не используются. Предыдущая установка сохраняется вне каталога скиллов; путь резервной копии печатается в конце. Обновление выполняется той же командой после изменения исходников.

Для другого каталога скиллов:

```sh
node scripts/install-local.mjs --target /path/to/skills/devflow-diff-explain
```

## Использование

В списке скиллов выбери **«Дифф — объяснить»** или явно вызови его в чате агента. По содержанию задачи скилл автоматически не запускается.

Пример явного вызова:

```text
$devflow-diff-explain <ссылка на PR>
```

Для Arcanum PR агент может запустить установленный producer одной командой. Из другого каталога укажи узкий подкаталог доступного Arc checkout:

```sh
node "$HOME/.agents/skills/devflow-diff-explain/bin/devflow-diff-explain-arc.mjs" \
  'https://a.yandex-team.ru/review/16729612' \
  --arc-dir /absolute/path/to/arcadia/billing/duty/balance_duty --lang ru
```

Команда через нативные `arc` и `ya tool gena-arcanum-cli` выбирает последнюю итерацию PR, включая черновую, экспортирует закреплённые ревизии и вызывает локальный `up`. Для конкретной итерации добавь `--diff-set <id>`. Нужны установленные Arc и `ya`, а также доступный Arc checkout; сам сервер к Arcanum не обращается.

Агент сам читает PR или локальные изменения доступными ему инструментами и скиллами. Он экспортирует полный инвентарь изменений и точные байты обеих сторон файлов; приложение импортирует готовый снимок. Внутри приложения нет адаптеров Arcanum/GitHub/Arc/Git, авторизации провайдеров и автоматического опроса PR: отдельный установленный Arc producer вызывает нативные инструменты и передаёт снимок через общий importer. Дополнительные источники, использованные в объяснении или ответе, агент импортирует перед публикацией.

Агент открывает локальный UI и строит объяснение. Начни с описания, затем прокручивай блоки и полные диффы файлов одной лентой в предложенном порядке. Содержание слева подсвечивает читаемый файл и позволяет перейти к любому месту. Обычный вопрос в чате относится ко всему PR. Для фокуса на файле нажми «В чат» рядом с его именем; для фокуса на коде выдели строки. Вложение видно возле ввода, его можно удалить. Все импортированные файлы, их полные патчи, оригиналы бинарных файлов и использованные источники доступны после завершения агента, удаления экспортного каталога и перезапуска сервера; генерация и ответы требуют воркера.

Сохранённые данные и настройки по совместимости находятся в `~/.sherpa`; переменная `SHERPA_DIR` задаёт другой каталог. Перенос проекта и обновление скилла эти данные не удаляют. Сервер слушает localhost. Новая версия появляется только после явного импорта, прежние вопросы и выбранный разбор сохраняются. У старого неполного кэша доступны только ранее сохранённые материалы; недостающие байты требуют явного импорта той же версии. Старые ссылки на изображение сохраняют свой ID после совместимого импорта полного снимка и открываются из локальной базы после перезапуска.

Ссылка запуска закрепляет импортированную версию кода ещё до обзора. Ссылка на конкретный разбор в интерфейсе открывает эту версию в отдельной вкладке, даже если уже импортирована следующая. После перезапуска порт и токен сервера могут измениться: агент повторно открывает сохранённый locator командой `up --pr <key> --code <codeSnapshotId> [--review <snapshotId>]` через установленный `.mjs`. Вопрос фиксирует показанную редакцию и вложение при отправке; повтор использует тот же контекст и историю.
