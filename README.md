# Devflow Diff Explain

Установка скилла: `pnpm install:local`. Рабочая сборка включает только сценарий объяснения: сервер не читает комментарии коллег и не подключает публикацию, черновики и фидбек. Прежний UI и код ревью сохранены для отдельной работы.

Исходники: `/path/to/devflow-diff-explain`. Скилл и команда запуска: `devflow-diff-explain`. Внутренние пакеты `@sherpa/*`, переменные `SHERPA_*` и каталог `~/.sherpa` сохранены для совместимости с существующими данными.

Личная сборка **0.16.0**: описание ПРа, смысловые блоки и файлы в порядке для понимания. У каждого файла краткое пояснение, полный сохранённый дифф и заметки только у важных строк. Переходы сохраняют место, выделение и раскрытый контекст; вопросы по файлу и строкам задаются явно в чате. Старый сценарий ревью сохранён в коде и скрыт. Скилл устанавливается копированием, без симлинка. Пояснения начинаются с назначения, сложные изменения получают короткий пример; схема в описании показывает общий поток и отмечает затронутые узлы и связи. Текущее поведение описано в [docs/design/story.md](docs/design/story.md), согласованные требования — в [спеке](docs/design/guided-diff-spec.md) и [дополнении о понятной подаче](docs/design/readable-flow-spec.md). Описание показывает маршрут справа, блок — назначения файлов до открытия диффа. Оформление Arcanum включается в верхней панели; глобальное меню сервисов не переносится. Детали пакета — в [зафиксированной цели и плане](docs/design/arcanum-reading-ui.md). Ниже сохранена документация исходного проекта.

Devflow Diff Explain — локальный инструмент код-ревью. Ревьюер читает дифф пул-реквеста в браузере, а ИИ-агент в соседней сессии его же харнеса строит по диффу **маршрут** — упорядоченный рассказ о том, что изменилось и какие у этого следствия, — и отвечает на вопросы прямо у строк кода. Сервер и UI поднимаются на localhost; наружу Devflow Diff Explain ходит только в хост PR — Арканум по вашему arc-токену или GitHub по вашему токену GitHub — и в Трекер (фидбек, по кнопке).

При этом UI — полноценная замена Арканума для ревью: дерево файлов и поиск, дифф с подсветкой и развёрткой контекста, треды и черновики комментариев, шип. Без агента всё это продолжает работать: маршрут — слой поверх читалки, а не её условие.

Для кого: ревьюер в Аркадии, Cloudia или на GitHub, у которого поток PR больше, чем можно прочитать построчно. Статус — ранняя сборка, MVP в разработке. Баги и странности случаются, о них есть куда написать (см. «Фидбек»).

## Что нужно

- Для PR в Аркануме — `arc`. Devflow Diff Explain берёт из него токен Арканума: `$ARC_TOKEN` → `~/.arc/token` → `arc token show --json`. Отдельной авторизации и браузерного OAuth нет.
- Для PR в Аркануме — смонтированный чекаут того репозитория, где живёт PR: Аркадии или Cloudia (`arc mount -r cloudia <путь>`). Из него Devflow Diff Explain читает сам дифф и содержимое файлов (метаданные PR по-прежнему из Арканума). Подойдёт любой живой маунт нужного репозитория: ни ветка, ни рабочее дерево значения не имеют, нужный чекаут Devflow Diff Explain находит сама. Такого чекаута нет — дифф не покажется, и Devflow Diff Explain скажет, чего ей не хватает.
- Для PR на GitHub — токен: `$GITHUB_TOKEN` → `$GH_TOKEN` → `gh auth token`. Чекаут не нужен, PR читается по API. Чтобы линза «Мои файлы» учитывала команды из CODEOWNERS (`@org/team`), у токена нужен скоуп `read:org`.
- Для локального ревью — чекаут arc или любой git-репозиторий.
- Node ≥ 22.13 (в линейке 23 — от 23.4: раньше там нет `node:sqlite`).
- Харнес агента: Claude Code (проверено) или Codex (заявлено, проверено меньше). Годится и любой другой — Шерпе нужны только поддержка скиллов и возможность вызвать bash.
- Модель: конфигурация обкатана на `opus:high` и `gpt-5.60-sol:high`, их и рекомендуем.

## Установка

Симлинк каталога `skill` в скиллы харнеса (путь к чекауту — ваш):

```
mkdir -p ~/.claude/skills ~/.agents/skills
ln -s ~/arc/arcadia/junk/alice/sherpa/skill ~/.claude/skills/devflow-diff-explain   # Claude Code
ln -s ~/arc/arcadia/junk/alice/sherpa/skill ~/.agents/skills/devflow-diff-explain   # Codex
```

Каталог самодостаточен: два собранных `.mjs` (CLI и сервер с зашитым UI), ноль рантайм-зависимостей, pnpm и чекаут репозитория не нужны. Можно не линковать, а скопировать куда угодно.

Обновление — `arc pull` в чекауте (для симлинка) или повторное копирование.

## Запуск

В сессии агента:

```
/sherpa https://a.yandex-team.ru/review/12345
```

Аргументом годится ссылка на PR в Аркануме или на GitHub, голый номер PR Арканума (`12345`) или ключ вида `arcanum-12345`.

Без аргумента (или с путём к каталогу) — локальное ревью: всё, что изменилось в каталоге относительно базы, закоммиченное и нет, в чекауте arc или git. База по умолчанию — merge-base с trunk в arc, в git — `origin/HEAD`, `main` или `master`; другую базу назовите агенту. Локальное ревью не превращается в ревью PR, даже если у ветки он есть. Комментарии из него никуда не публикуются: их получает агент в той же сессии как просьбу поправить код, а ответы приходят в те же треды.

UI открывается в браузере сам, а ссылку агент печатает в любом случае. Ссылка локальная, токен доступа лежит в ней самой — никуда её не публиковать. По SSH и в headless-окружении автооткрытие лишнее: попросите агента добавить `--no-open` и откройте напечатанную ссылку руками.

Дальше агент крутит петлю и ждёт задачи из UI.

### Прямой доступ к виртуалке по IPv6

По умолчанию сервер слушает только `127.0.0.1`. Для доступа по сети запустите новый сервер
с `SHERPA_LISTEN_HOST=::`: он будет принимать IPv6- и IPv4-соединения, включая локальные
запросы CLI, а `devflow-diff-explain up` напечатает ссылку с DNS-именем виртуалки. Переменная применяется
при старте сервера; уже работающий сервер нужно перезапустить.

Такой запуск открывает порт на сетевых интерфейсах. Проверка токена сохраняется, но HTTP
не шифрует соединение. Для шифрованного доступа используйте SSH-туннель или HTTPS-прокси.

## Что умеет

### Маршрут

Маршрут начинает строиться сам: как только к серверу подключился агент-воркер и загрузился дифф, сервер ставит задачу в очередь. Руками — «Построить маршрут» на Обзоре, в баннере или командой палитры: перезапустить после ошибки, перестроить после пуша, начать, если автозапуск не сработал. Остановки появляются по мере генерации — UI работает, не дожидаясь конца. Каждая остановка — заголовок, абзац «что изменилось → какие следствия», якоря на диапазоны строк и настоящая читалка диффа внутри: комментировать, отмечать просмотренным, раскрывать контекст можно прямо там.

У остановок есть важность — high / medium / low; low свёрнуты по умолчанию. Порядок переключает пресет: «Триаж» (по важности) ↔ «Полный тур» (точка входа → определения → следствия → верификация). Всё, что модель не разложила, честно сваливается в остановку «Прочее» с пометкой «не разложено» и кнопкой попросить агента разложить; в полном диффе необъяснённое помечено штриховкой. Маршрут проходит валидатор: ссылку на несуществующий файл и утверждение без якоря он отбрасывает, а остановка говорит, сколько отброшено.

У малого PR (до 40 изменённых строк) маршрута нет вовсе — сразу открывается дифф.

### Три экрана

- **Обзор** — стартовый: шапка PR, «Кратко», файлы по зонам ответственности a.yaml с сегментами «Моя зона / Все», карточка «Обсуждение» (участники со счётчиками, треды уровня PR, клик по автору оставляет в диффе только его треды).
- **Маршрут** — повествование и дифф в одной ленте; третья панель (чат, треды) открывается по требованию.
- **Полный дифф** — классическая читалка: дерево файлов, линзы, поиск, ИИ-слой на полях.

### Читалка диффа

Unified и split, подсветка синтаксиса и словесная подсветка внутри строки, заголовки сущностей («функция X изменена · 120–164»), схлопнутые неизменённые куски, виртуализация под большие диффы. Картинки показываются картинками: «было / стало» рядом, шторка, наложение, разностный слой, масштаб 1:1 или по ширине.

В файлах `.md`, `.markdown` и `.mdown` кнопка **Markdown** включает отображение документа; **Код** возвращает исходник. Выделите несколько слов или предложение и выберите «Спросить агента» — в вопрос попадёт точная цитата вместе с контекстом строк. Через «Комментировать» можно оставить обычный комментарий ревью: он привязан к тем же строкам и виден в обоих режимах. Для изменённого документа доступны версии до и после правки; пропущенный контекст раскрывается в режиме кода.

Линза «Мои файлы» считает только правила a.yaml, которые призвали именно вас. Линза PCI DSS появляется, только если PR действительно трогает файлы из скоупа аудита. Машинные файлы приглушены и по умолчанию считаются просмотренными. Правый клик по файлу (или «⋯» в шапке карточки и в дереве): скопировать путь, скопировать ссылку на файл в Арканум, открыть файл в вебе хоста (в Аркануме или на GitHub), отметить просмотренным.

Отметки просмотренных файлов синхронизируются с Арканумом в обе стороны: ваша отметка уходит туда (если хост это умеет), арканумные приезжают обратно, при расхождении сильнее локальная. Локальными остаются отметки остановок маршрута, построчное покрытие и дефолт «машинные файлы просмотрены». Просмотренное схлопывается, и прогресс виден по плотности кода на экране. После «Просмотрено» экран переходит к следующему файлу — в маршруте к следующей остановке.

### Комментарии и шип

Треды Арканума Devflow Diff Explain перечитывает по таймеру и привязывает к диапазонам и остановкам: счётчики на остановках, фильтры по автору, боту и статусу, переход из треда к месту в маршруте, метка источника у нейро-ревьюера. Треды, которые Арканум пометил устаревшими, несут чип «закреплён за 9f3c1ab» и кнопку показать их на старом коммите. Закрытые треды и боты приглушены по умолчанию.

Модель публикации двухступенчатая: черновик уходит в Арканум мгновенно, а накопленное — пакетом при завершении. Перед шипом Devflow Diff Explain показывает сводку — что именно уйдёт. Недописанный комментарий переживает перезагрузку вкладки. В комментариях работают списки, цитаты, заголовки, таблицы, чек-листы, блоки кода и зачёркивание; в редакторе — горячие клавиши как в Notion (`- ` и `1. ` начинают список, ``` — блок кода, Enter и Tab ведут себя по-списочному).

Вердикт: Ship (одобряет только этот снапшот), Sticky ship (переносится на следующие пуши) и «Есть замечания». Кнопка «Опубликовать · N» отправляет черновики без вердикта. Панель показывает только то, что примет хост: на своём PR в GitHub и в локальном ревью остаётся одна публикация, Sticky ship есть только в Аркануме и только если его разрешают настройки PR.

### Чат с агентом и заметки

Выделите строки в диффе — поповер предложит «Спросить агента». Вопрос уходит в ту же сессию, ответ приходит в панель чата (индикатор агента в верхней панели её открывает) и остаётся у этих строк сворачиваемой заметкой. Заметка локальная, в Арканум не уходит, но в один клик превращается в черновик комментария с пометкой «процитировано из ответа агента». Вопрос без выделения — про PR целиком. Пока агент строит маршрут, вопрос ждёт в очереди — панель и индикатор это показывают.

Неизменный контекст задач (дифф PR, текст файла, методички) агент читает один раз за сессию: пять вопросов подряд не стоят пяти чтений диффа. История чата живёт per-PR; `@` в палитре ищет по ней, включая прошлые итерации, и ведёт к строкам, если якорь жив.

### Итерации: второй заход после пуша

Автор дослал коммит — Devflow Diff Explain замечает это сама, без перезапуска, и показывает баннер «Маршрут устарел» с номерами задетых остановок. «Перестроить маршрут» строит второй заход: агент получает прошлый маршрут, разницу между итерациями и обсуждение на тронутых строках, а сервер помечает остановки как «изменилась» / «новая» и переносит прогресс — остановки на нетронутых строках остаются просмотренными, баннер называет их число.

Кнопка «Что нового с прошлого захода» (клавиша `w`) оставляет на экране только изменившееся, у каждой остановки — «почему изменилась» со ссылками на треды. Заметки чата переезжают вместе со строками; те, что привязать больше не к чему, Devflow Diff Explain помечает «якорь потерян после пуша» и оставляет в чате.

Индикатор снапшота в верхней панели — меню: прошлые снапшоты и итерации открываются в режиме чтения (комментировать и отмечать можно только в активной), «Показать изменения с итерации…» открывает разницу между двумя пушами без маршрута. Force-push историю не ломает: снапшот исчезнувшего коммита Devflow Diff Explain читает из локальной копии. На GitHub прошлых итераций нет — там ревьюится текущая голова ветки.

### Клавиатура

Всё ревью проходится с клавиатуры: полная карта — по `?`, командная палитра — `⌘K`.

| Клавиши | Что делает |
|---|---|
| `1` / `2` / `3`, `g o` / `g r` / `g d` | Обзор, Маршрут, Полный дифф |
| `j` / `k` | следующая-предыдущая остановка (в полном диффе — файл) |
| `n` / `p` | следующая-предыдущая непросмотренная |
| `v` | отметить просмотренным |
| `e` | раскрыть контекст ханка |
| `x` | свернуть или раскрыть остановку |
| `c` / `r` | комментарий к строке / ответ в тред |
| `a` | спросить агента о выделении |
| `f` | найти файл (в полном диффе — фильтр файлов в дереве) |
| `/` | поиск по содержимому диффа |
| `d` | режим диффа |
| `t` | пресет маршрута |
| `w` | фильтр «что нового с прошлого захода» |
| `⌘K` / `?` | палитра команд / карта клавиш |
| `⌘⏎` / `⌘⇧⏎` | меню шипа / «Есть замечания» |

### Первый заход

При первом открытии Devflow Diff Explain проводит короткий тур по экрану — восемь шагов, `→` или `Enter` дальше, `←` назад, Esc закрывает. Повторить: палитра ⌘K → «Показать онбординг заново».

### Язык интерфейса

Русский или английский. По умолчанию язык приходит от агента — скилл передаёт его сам (`devflow-diff-explain up --lang`), — а без агентской сессии от браузера. Сменить вручную: палитра ⌘K → «Язык интерфейса: английский» / «: русский»; вернуть автоматический выбор — «Язык: авто». Выбор глобальный, переживает перезапуск и действует на все PR.

На этом же языке агент пишет маршрут и отвечает в чате. Язык генерации Devflow Diff Explain запоминает в момент постройки маршрута: если потом сменить язык интерфейса, индикатор провенанса назовёт язык маршрута, а плашка предложит перестроить его на новый — старый маршрут сам не переводится.

### Тема интерфейса

Светлая и тёмная. Кнопка в верхней панели показывает текущую тему и переключает её без
перезагрузки. Выбор сохраняется для всех PR и переживает перезапуск. По умолчанию — тёмная.

### Обновления

Сервер сверяет версию каталога скилла с trunk — не чаще раза в 30 минут, результат кэширует, чтобы серверы всех ваших PR не долбили API. Если в trunk версия выше вашей, в левом нижнем углу появляется тост: что нового одной фразой и как обновиться. Ничего не скачивается и не ставится само. Проверить прямо сейчас: палитра ⌘K → «Проверить обновления». «Не напоминать про X» глушит ровно эту версию, следующая покажется снова.

### Настройки

Настройки не слетают при запуске: режим диффа, режим шипа, раскладка редактора, язык, тема и состояние онбординга лежат в `~/.sherpa/settings.json` (общие для всех PR), а свёрнутые каталоги, карточки и недавние команды палитры — в базе конкретного PR.

## Переменные окружения

Ни одна не обязательна: без них Devflow Diff Explain работает на значениях по умолчанию.

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `ARC_TOKEN` | Токен Арканума, первый в цепочке | `~/.arc/token`, затем `arc token show --json` |
| `SHERPA_DIR` | Корень состояния Шерпы | `~/.sherpa` |
| `SHERPA_PR` | Ключ PR, когда не задан `--pr` | не задан; дальше по цепочке — PR текущей arc-ветки |
| `SHERPA_LISTEN_HOST` | Адрес прослушивания нового сервера; `::` включает IPv6 и IPv4 | `127.0.0.1` |
| `SHERPA_SERVER_BIN` | Путь к модулю сервера | соседний `devflow-diff-explain-server.mjs` в каталоге скилла |
| `SHERPA_TRACKER_TOKEN`, `TRACKER_TOKEN`, `STARTREK_TOKEN` | OAuth-токен Трекера для кнопки Feedback; берётся первый непустой | не задан — токен добывает `ya tool fetch-token -preset startrek` (`ya` ищется в PATH и в корне чекаута Аркадии); не вышло — кнопка говорит, что канал недоступен |
| `SHERPA_IDLE_SECONDS` | Отладочная. Порог самоостановки в секундах, `0` — выключить | `900` (15 минут) |
| `SHERPA_WORKER_ID` | Отладочная. Пин идентичности сессии-воркера | идентичность из файла `worker-id` этого PR |
| `SHERPA_SERVER` | Отладочная, только для дев-сервера UI: адрес живого сервера для прокси `/api` | манифест первого запущенного сервера |

## Что лежит на диске и что уходит наружу

Всё состояние — в `~/.sherpa` (каталоги 0700, манифесты 0600):

- `servers/<ключ PR>.json` — манифест живого сервера: порт, pid, токен доступа.
- `prs/<ключ PR>/sherpa.db` — SQLite этого PR: снапшоты маршрута, прогресс, черновики, история чата, состояние UI.
- `prs/<ключ PR>/server.log` — лог сервера.
- `prs/<ключ PR>/worker-id` — идентичность сессии-воркера (env не переживает отдельные вызовы харнеса).
- `prs/<ключ PR>/payload/` — файлы контекста задач, которые читает агент.
- `prs/<ключ PR>/blobs/` — кэш картинок диффа.
- `settings.json` — глобальные настройки UI.
- `update-check.json` — кэш проверки версии.

Наружу уходит четыре вещи:

- **Арканум** по вашему arc-токену: метаданные PR и список изменённых файлов, треды, публикация комментариев, шип, зоны a.yaml, скоуп PCI DSS. Сам дифф и содержимое файлов читаются из локального чекаута `arc`.
- **GitHub** — только для PR на github.com, по вашему токену: метаданные PR, дифф и содержимое файлов, треды, черновики и публикация, отметки просмотра, CODEOWNERS и состав команд организации.
- **Трекер** — только когда вы нажали Feedback и только при наличии токена Трекера.
- **Проверка обновлений** — чтение `skill/version.json` из trunk через API Арканума, не чаще раза в 30 минут.

Больше ничего: телеметрии нет, сервер по умолчанию слушает `127.0.0.1`, токен доступа к UI живёт во фрагменте ссылки и на сервер не уходит.

## Если что-то пошло не так

**Лог сервера** — `~/.sherpa/prs/<ключ PR>/server.log`, по-русски. Если демон вообще не поднялся, CLI сам печатает хвост лога в 20 строк.

**Сервер умер, а манифест остался.** Следующий запуск проверяет pid из манифеста и `/healthz` на его порту; протухший манифест он уводит в сторону и занимает место сам — руками ничего делать не нужно. Если хочется прибраться, файл `~/.sherpa/servers/<ключ PR>.json` можно удалить, пока сервер не запущен.

**`worker_conflict` и «stop the loop».** Слот воркера на PR один: новая сессия вытесняет старую, и старая получает ошибку с текстом «stop the loop» и останавливает петлю. Это норма, а не сбой — продолжайте в новой сессии. Двух агентов на одном PR не бывает.

**Сервер выключился сам.** Пятнадцать минут без открытых вкладок и без вызовов CLI — и сервер PR останавливается: команды `down` в нём нет, иначе он висел бы в памяти до перезагрузки машины. Вкладка скажет «Сервер недоступен, переподключаюсь…». Запустите `/sherpa <PR>` снова — состояние лежит в SQLite и остановку переживает.

**UI показывает «агент отключён».** Сервер жив, а сессии-воркера нет: её закрыли, перезапустили или вытеснили. Читалка при этом полная — дифф, поиск, комментарии, шип, ранее построенные снапшоты маршрута; недоступны только новые вопросы и генерация. Кнопка «Подключить агента» в верхней панели даёт команду запуска: выполните её в любом харнесе, и сессия снова станет воркером.

## Фидбек

Кнопка Feedback в UI заводит тикет в очереди [SHERPA](https://st.yandex-team.ru/SHERPA) — с вашим текстом и, если не снять галочку, с контекстом (версия, PR, экран, фаза маршрута, воркер). Контекст видно до отправки.

Нужен OAuth-токен Трекера. Сервер берёт его из окружения (см. таблицу выше), а если там пусто — при первой отправке запускает `ya tool fetch-token -preset startrek`; `ya` ищется в PATH и в корне чекаута Аркадии, из которого запущен или в который установлен сервер. Не вышло и так — кнопка честно говорит, что канал недоступен, а текст остаётся в форме для копирования.

Вопросы, обсуждение и фидбек без тикета — в [чате Шерпы](https://github.com/Buggytheclown/devflow-diff-explain/issues); ссылка на него есть и в самой форме Feedback.

## Границы

- Один PR на сессию, одна сессия на PR.
- Хосты — Арканум (Аркадия и Cloudia), GitHub и локальный чекаут arc или git.
- Собственных находок Devflow Diff Explain не генерирует: показывает существующие комментарии, включая нейро-ревьюера.
