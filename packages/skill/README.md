# @sherpa/skill

Пакет скилла Шерпы для харнесов (`docs/architecture.md §1`). Дистрибутив — каталог `dist/`: копия `SKILL.md` с инструкцией сессии, CLI и модуль сервера в `dist/bin/`. Ничто в рантайме не смотрит в чекаут репозитория и не зовёт pnpm.

- `SKILL.md` — что делает харнес: определить ключ PR (либо оставить его `devflow-diff-explain up`, который определит PR по arc-ветке каталога запуска), выполнить `devflow-diff-explain up` (он поднимает сервер и регистрирует сессию воркером), отдать ревьюеру ссылку на UI и крутить петлю `devflow-diff-explain worker next` (`docs/protocol.md §3, §7`).
- `dist/bin/devflow-diff-explain.mjs` — единственная команда, тонкий CLI без сервера и UI: петля воркера дёргает его на каждый вызов, поэтому старт должен оставаться быстрым.
- `dist/bin/devflow-diff-explain-server.mjs` — модуль сервера PR с зашитой статикой UI, не исполняемый. Его грузит `import()` только `devflow-diff-explain server` — процесс, который `devflow-diff-explain up` демонизирует как `node <каталог bin>/devflow-diff-explain.mjs server …`; путь к модулю можно переопределить `SHERPA_SERVER_BIN`.

Каталог `dist/` целиком — артефакт сборки, в git не хранится.

```
pnpm --filter @sherpa/ui build
pnpm --filter @sherpa/skill build
```

Сборка скилла собирает модуль сервера и CLI и складывает дистрибутив в `dist/`. Сборка UI в цепочку не входит: модуль сервера зашивает `packages/ui/dist` и падает с инструкцией, если UI не собран.

Установка в харнес — симлинк дистрибутива: `~/.claude/skills/devflow-diff-explain` → `<репо>/packages/skill/dist`. Каталог можно и просто скопировать куда угодно — он самодостаточен.

## Релиз

```
pnpm release --notes "<фраза>" [--target <каталог>] [--skip-build]
```

`scripts/release.mjs` собирает цепочку, сверяет `devflow-diff-explain --version` и `dist/version.json` с версией корневого `package.json` (единственный источник) и пересоздаёт каталог `skill/` в целевом каталоге. Цель по умолчанию — корень самого репозитория: дистрибутив лежит рядом с исходниками и уезжает в Аркадию тем же коммитом, `--target` нужен для прогонов в отдельный каталог.

`--notes` обязателен: одну фразу «что нового» показывает тост обновления, она едет в выложенный `skill/version.json` вместе с датой релиза. README дистрибутива — корневой `README.md` репозитория; релиз его не копирует, только проверяет, что номер версии в нём стоит. `arc` скрипт не зовёт — печатает готовые `arc add skill` и `arc commit` для ручного запуска.
